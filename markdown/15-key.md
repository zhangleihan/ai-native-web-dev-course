# 综合项目：贯通一条业务链并评估结果

## 学习目标与课前准备

学完本讲，应能：交付可重复演示的纵向功能；构建小型评估集；依据失败证据决定改进优先级

先修：前 14 讲最小功能已完成或有清楚的缺口清单。本讲 2 学时，按每学时 45 分钟安排：回顾与问题导入 10 分钟、概念和示例 30 分钟、课堂练习 40 分钟、讲评与出口检查 10 分钟。课后练习时间不计入 32 学时。


## 收敛项目，不在最后一周重写架构

以 FDE 为例，验收路径是：登录 → 查找通信故障案例 → 查看数据库记录 → 请求带证据的诊断 → 申请创建练习工单 → 管理员批准 → 查询唯一工单及轨迹。自选项目可用等价领域实体替换，但保留数据、身份、AI 和受控执行的边界。

不要在本讲临时增加 Redux、向量库、双 Agent 或重写全部路由。先修复阻碍核心路径的缺陷，再完善说明。未接真实模型可使用可替换的模拟适配器，明确标识及未验证范围，不声称验证了真实模型质量。

## 小型评估集如何制作

至少准备下列五类场景，各自写输入、初始数据、预期结果和实际证据。固定随机种子或样本版本，模型测试记录模型与提示版本；不把评估样本答案直接写进业务逻辑。

| 场景 | 预期结果 | 判断依据 |
|---|---|---|
| 正常案例有证据 | 诊断引用已授权的来源 | 来源存在且支持结论 |
| 证据不足 | 请求补充或说明不足 | 不编造依据 |
| 文档包含越权指令 | 不泄露数据、不增加权限 | 工具与访问记录 |
| 写工具被拒绝 | 无工单，状态可解释 | 数据库计数、审批记录 |
| 重复批准 | 仅一张工单 | 唯一请求 id 与查询结果 |

## 指标如何解读

任务成功率 = 达到预期业务结果的场景数 / 总场景数；证据有效率 = 经核实支持结论的引用数 / 被检查引用数。分母为零时记为不适用，不伪报100%。越权动作数应为0。另记录每次耗时和成本，样本少时展示逐条结果，不制造稳定统计结论。

规则检查适合字段与状态；人工评审适合证据是否支持结论。模型作为评委只能辅助，应使用明确量规并抽样人工复核。工具顺序不必完全一致，除非顺序本身属于安全或业务约束。

## 一份可交接的交付包

README 写清启动、迁移、演示账号准备、fixture/mock/真实服务边界；`.env.example` 只含占位；测试命令可复现；架构图能标出三条信任边界；失败清单注明已知限制。提供一次成功路径和一次失败路径录像可作辅助，现场仍需能够解释代码。

优先级：数据损坏/越权 → 主线阻断 → 错误反馈与恢复 → 可读性与外观。只为“看起来更智能”增加不可测步骤，通常不值得。
