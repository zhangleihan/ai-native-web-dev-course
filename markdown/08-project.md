# 项目关联：把UI身份接到服务端权限

## 本讲在主线中的位置

前几讲提供页面、API和持久化，本讲建立“已验证身份—资源归属—允许操作”的关系。先保护一个核心资源，随后把同一原则迁移到运行、审批与后台功能。

| 当前原型行为 | 服务端需要补充 | 验证方式 |
|---|---|---|
| 切换演示角色 | 真正认证与会话恢复 | 未登录不能写入 |
| 创建本地记录 | 服务端分配owner | 伪造owner/role无效 |
| 隐藏编辑按钮 | 每次请求检查目标权限 | 直接请求他人资源仍被拒绝 |
| 点击退出清空头像 | 销毁服务端会话 | 旧Cookie重放失败 |
| 展示用户标题 | 正确文本输出 | 标签不会被解释为HTML |
| 显示审批按钮 | 角色、资源与状态检查 | 普通用户403，非法状态409 |

FDE UI副本的角色选择目前是演示状态，不具备本讲认证能力。接入时应先实现登录与GET会话恢复，再为一个资源设计所有权；不要把前端角色字符串直接传给后端作为权限。

## 参考源码

course-lab/server/app.mjs组织会话与CSRF；domain.mjs选择公开用户字段与业务输入；MemoryStore/PgStore执行归属检查；client/api.js保存当前CSRF，React页面根据服务端身份展示。

数据库users/owner_id来自综合实验，不与第6讲authors教学表混用。本讲新增测试默认运行内存适配器，数据库权限和多实例会话另行验证。

## 最小完成范围

为期末项目一个资源写权限表，完成登录恢复、本人修改、他人拒绝和退出失效。至少保存一次拒绝前后数据比较，说明凭据如何携带、CSRF在哪里校验、未完成的生产能力有哪些。

## 选修拓展

按项目需要继续研究组织隔离、权限变更、单点登录、MFA或密码恢复。采用成熟方案并验证具体边界，不通过新增几个前端按钮声称完成身份系统。
