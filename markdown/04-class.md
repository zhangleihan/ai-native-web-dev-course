# 课堂练习：亲手完成受控筛选与状态提升

## 准备与安排

使用 [React 基础实验](labs/react-basics/README.md)，课前完成 `npm ci`。课堂练习占本讲计划中的30分钟；另外的讲授与演示合计60分钟。完整参考实现已经提供，但练习必须在自己的副本中做一项尚未实现的功能，并解释其数据流。

建议先复制整个 `labs/react-basics` 到自己的练习目录（不要复制 node_modules），再安装依赖。教师演示时可切换三个阶段；学生先只看 StaticPage.jsx 与 SearchPage.jsx，尝试后再对照 App.jsx。

## 第一步：读懂组件与输入（5分钟）

运行阶段一，找到数据来源与 `map`。把一张卡片标题改为自己的案例名，不增加新的卡片组件。切换阶段二，输入“链路”“不存在”，然后清空输入。指出：哪个变量是 state，哪个变量是派生结果，哪个标签使用了受控值。

验收：一个组件能展示多条不同数据；1条、0条、全部三种结果与计数一致。

## 第二步：独立增加难度筛选（12分钟）

在阶段二 `SearchPage.jsx` 上扩展，不要直接复制完整阶段三覆盖它。

1. 增加 `difficulty` 状态，初值 `'all'`。
2. 加入带 label 的 select，三个 option 值分别为 `all`、`beginner`、`intermediate`。
3. 使用 value 与 onChange 连接状态，检查读出的值。
4. 在原关键词过滤条件后增加 `&&`：难度为 all 或 item.difficulty 与选项相同。
5. 增加 `type="button"` 的清空按钮，同时重置两个筛选条件。

先写出预期再执行：全部为3条，入门为1条，进阶为2条；关键词“链路”与进阶组合为0条，清空后为3条。不要另存结果数量，不要用 Effect 同步过滤结果。

## 第三步：提升状态并解释收藏（8分钟）

把第二步输入控件拆为 `SearchFilters`：通过 props 接收两个当前值与两个回调。状态仍放在父组件，结果列表仍由父组件计算。不要在子组件复制一份 keyword 或 difficulty。

随后阅读阶段三 `App.jsx`，两人互相追踪一次收藏操作：卡片传什么参数、谁调用 setter、谁重新计算、列表和统计分别收到什么值。把其中一张卡片的收藏动作与“只看收藏”组合起来验证。

## 第四步：验收与讲解（5分钟）

| 场景 | 预期 | 证据 |
|---|---|---|
| 关键词与难度同时筛选 | 取交集，计数与列表一致 | 组合条件截图 |
| 没有匹配项 | 显示空态，输入控件仍可用 | 空态截图 |
| 清空筛选 | 选项回默认，全部案例恢复 | 重置后截图 |
| 收藏与统计联动 | 列表按钮、计数使用同一份状态 | 指出父组件状态位置 |
| 仅收藏时取消最后一项 | 列表为空，数量为0 | 操作记录 |

提交修改的源文件、至少3条实际测试记录，以及80–150字的数据流说明。截图仅作辅助，不能代替可运行代码。教师重点询问“为什么状态放这里”和“哪些数据无需 state”，不以代码行数评价完成度。
