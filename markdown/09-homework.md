# 课后练习：可恢复的任务进度面板

## 必做（建议45–60分钟）

在本讲实验或期末项目UI中，完成一个任务反馈面板：创建一次任务，展示任务状态、连接状态与事件位置；支持停止订阅、重新订阅、查询快照和明确取消。可使用固定模拟步骤，不调用付费模型。

解释创建、快照、订阅、取消四个接口。提供正常完成、断开恢复、取消、业务失败、历史不足五种结果记录。重连不得再次创建任务，日志去重范围须包含任务编号，终态与done的关系须明确。

## 分步完成

1. 运行参考实验，画出一个任务与两个订阅之间的关系。
2. 修改页面布局或业务阶段，使其对应自己的期末主题，保留模拟标识。
3. 解释一个Effect的建立、依赖和清理，找出游标保存位置。
4. 新增一条有意义的测试或独立验证记录，例如重复取消后序号不增加；不要只断言内部函数被调用。
5. 记录一个尚未验证的部署条件，以及检查它的方法。

## 提交内容

通过北邮云邮教学空间提交源码或仓库、相对路径运行命令、接口简表、结果记录，以及约200字的设计说明。说明中解释“断线不等于取消”和“恢复快照不等于恢复全部历史”。使用AI时简述参与范围与一次人工核查，不提交密钥、口令或私人对话。

## 自评标准

| 维度 | 完成标准 |
|---|---|
| 生命周期 | 一个创建动作对应一个任务，观察与执行分开 |
| 界面反馈 | 业务与连接状态分别显示；失败可见 |
| 恢复与去重 | 位置明确，重复消息不重复追加；历史缺口可说明 |
| 取消与资源 | 取消是显式操作；卸载关闭连接；终态保持 |
| 证据 | 记录与真实请求一致，标注模拟与未验证范围 |

不以消息数量或复杂组件数量评分。先完成可靠的最小闭环，再增加视觉细节。

## 选做

实现无重叠轮询版本，与SSE比较相同任务的请求次数与发现延迟；为任务增加跨刷新恢复；在测试存储中持久化快照与事件。比较实验需说明网络、间隔和采样方式，不能把一次本机结果当作普遍性能结论。
