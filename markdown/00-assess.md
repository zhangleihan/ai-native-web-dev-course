# 考核与授课方式

比例沿用课程大纲（与旧课介绍页一致）：

| 项目 | 占比 | 说明 |
|---|---|---|
| 课堂考勤 | 10% | 到课、参与 Golden Path / 当堂演示 |
| 课堂练习、课后练习、期中练习 | 40% | 「课后练习」；期中检查案例库走 HTTP、登录与库表是否落地 |
| 课程作业 | 50% | **1–4 人分组**：完成一项完整网络应用系统（游戏、网络应用，或参与开源项目的证明） |

## 课程作业期望

完成一项**完整的网络应用系统**，用到完整的动态网络开发技术：**前后端完整、功能完善、能正常运行**。选题可以是：

- **游戏**
- **网络应用**（自选业务场景）
- **参与开源项目的证明**（需能说明本人贡献，且贡献体现动态 Web / 全栈能力）

验收时能当场启动并走通核心功能；仓库含 README（如何启动、账号与环境、功能说明）；密钥不进 Git。

## 分组

1–4 人。第 0 讲结束后在微信群报组，并在在线表格填写 GitHub 代码仓库，用于提交平时作业和课程项目，添加zhangleihan@gmail.com访问权限（见「教师、微信群与开发环境」一节的文档链接）。
