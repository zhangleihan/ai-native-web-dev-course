# 课后练习：为一个资源建立可测试的权限边界

## 必做

为期末项目选择一个资源，写出匿名、所有者、其他普通用户、管理员的操作矩阵。实现登录身份恢复、资源归属、写请求防护与退出失效；可沿用服务端会话骨架。

至少验证：有匿名CSRF的未登录写入、所有者合法操作、跨用户修改、伪造owner/role、错误CSRF、退出后重放。记录状态码、错误层次与数据副作用，不以隐藏按钮作为授权证明。

## 提交内容

提交权限表、源码或修改差异、相对路径运行说明、请求与响应摘要、验证记录。标明Cookie/CSRF/身份分别由哪层管理，证据中移除完整凭据。使用AI时说明参与内容和一次自己发现的错误。

## 自评标准

| 维度 | 自评问题 |
|---|---|
| 身份 | 是否来自服务端验证，而非客户端声明？ |
| 资源 | 是否每次检查对象归属与允许操作？ |
| 失败 | 是否拒绝且不产生未经授权的变化？ |
| 会话 | 登录是否轮换，退出是否使旧凭据失效？ |
| 浏览器 | 是否区分XSS、CSRF、CORS与Cookie属性？ |
| 范围 | 是否明确尚未验证的HTTPS、数据库或多实例行为？ |

## 选做

选择一项：测试角色降权后的旧会话；设计团队/组织隔离；比较JWT与会话撤销；评审密码恢复流程。JWT、OAuth和生产身份提供方集成不要求全部实现。
