# 从页面到 AI 原生应用：请求链与系统边界

## 学习目标与课前准备

学完本讲，应能：画出一次查询的数据流；区分浏览器、服务端和数据库的职责；用可验证需求描述一个 AI 功能

先修：能使用终端和浏览器，能阅读基本变量、条件与函数。本讲 2 学时，按每学时 45 分钟安排：回顾与问题导入 10 分钟、概念和示例 30 分钟、课堂练习 40 分钟、讲评与出口检查 10 分钟。课后练习时间不计入 32 学时。


## 从一个真实问题开始

通信网络故障处理案例库要回答两个问题：“有哪些可学习的案例？”“某个诊断建议依据什么？”前者适合确定性的数据库查询；后者可以引入模型辅助解释，但必须展示证据。先做可靠查询，再增加 AI，不能用聊天框掩盖数据缺失。

本课最小系统为：案例列表 → API → 数据库 → 登录与权限 → 诊断建议 → 经审批创建**练习工单**。无需一次实现 FDE 平台的所有菜单。没有平台仓库时也可用独立小应用完成相同目标。

## 一次请求的分工

```text
浏览器：点击筛选 → GET /api/cases?industry=telecom
服务端：校验查询条件 → 参数化 SQL
数据库：返回匹配记录
服务端：JSON {items: [...], total: 1}
浏览器：更新列表，并展示空结果或错误
```

域名访问通常还涉及 DNS、建立连接和 TLS；有缓存时不一定每次都重新查询 DNS。HTTP 是应用层协议；HTTPS 在传输中提供加密与服务器身份验证。浏览器收到 HTML 后构造 DOM，加载样式和脚本，再由事件驱动后续请求。

浏览器里的状态刷新后可能消失；数据库中的状态通常跨进程重启保留。显示了“保存成功”不等于真的持久化，要关闭服务、重新启动后验证。模型生成的句子也不是数据库事实。

## MPA、SPA 与 AI 是不同维度

MPA 常在导航时向服务端请求新页面；SPA 常在初次加载后由 JavaScript 更新视图。两者都可以调用 AI 服务，也都可以结合服务端渲染。React 是 UI 库；Next.js 提供路由、服务端渲染等能力。本课先讲浏览器 React 与独立 Express API，已有 Next 项目可做等价实现，不同时学习两套后端。

Next 的 `'use client'` 声明客户端组件边界，并不意味着初次访问绝不会预渲染 HTML。判断代码在哪里运行，要看框架边界和实际请求，而不是只看文件后缀。

## 从界面猜测到证据

打开 DevTools 的 Network，清空记录，再执行一次筛选。记录请求 URL、方法、状态和响应。没有新请求可能是客户端本地筛选、缓存或已有数据，不能直接断言应用没有后端。沿源码继续找到数据入口。

给数据标注来源：fixture（课堂固定样本）、mock（模拟服务响应）、database（真实数据库）、model（模型生成）。开发时 mock 有用，但演示和验收必须明确标示。

## 本学期的需求样例

“用户按行业查询案例，存在匹配时展示标题；没有匹配时提示空结果；服务不可用时展示可重试错误。AI 给出诊断建议时附案例编号，证据不足时明确说明。”这比“做一个智能平台”更容易实现和测试。

扩展阅读中的多 Agent、复杂领域本体、自动长期记忆均为选修，不作为基本完成条件。
