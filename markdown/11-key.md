# 部署与持续集成：可复现环境和数据生命周期

## 学习目标与课前准备

学完本讲，应能：说明镜像与容器；区分代码、配置和持久数据；设计失败即停止的 CI 检查

先修：已有可运行 API、测试命令和依赖锁文件。本讲 2 学时，按每学时 45 分钟安排：回顾与问题导入 10 分钟、概念和示例 30 分钟、课堂练习 40 分钟、讲评与出口检查 10 分钟。课后练习时间不计入 32 学时。


## 能在另一台机器运行才算交付

镜像封装应用与运行依赖，容器是镜像的运行实例；数据库卷保存需跨容器生命周期保留的数据。把数据写进临时容器文件系统，不等于备份。Compose 描述多个服务如何连接，不能自动替你完成迁移、权限或恢复演练。

课堂使用已有容器骨架做改造，不在两学时内完成云平台、反向代理、证书和集群编排。没有 Docker 的学生可完成环境清单和配置评审，容器验证在教师环境完成并记录执行者。

## 容器里容易混淆的 localhost

浏览器的 localhost 指用户电脑，API 容器的 localhost 指该容器。Compose 中 API 连接数据库应使用数据库服务名，例如 `db:5432`。浏览器不能直接解析 Compose 内部服务名，应通过发布的端口或统一 Web 入口访问 API。

第 5 讲服务仅监听 `127.0.0.1`，容器化时需按部署环境改为 `0.0.0.0`，并控制端口暴露。仅复制同一代码进镜像但不改监听地址，会导致宿主机无法访问。

## 配置与秘密

提供 `.env.example` 列出变量名和用途，不填真实密钥；实际凭据通过受控运行环境注入。前端打包产物公开可读，任何打包进去的 key 都不再是秘密。Next 的公开前缀变量常在构建时嵌入，不能假设改容器环境就会改变已打包页面。

| 操作 | 应关注的结果 |
|---|---|
| stop / start | 停止和恢复现有容器，不代表应用已卸载 |
| 重建应用容器 | 代码更新，数据库卷应继续保留 |
| 删除卷 | 可能永久丢失练习数据，不用于常规“重启” |
| 数据库备份恢复 | 需验证恢复出的记录，不只检查文件存在 |

## CI 最小流水线

```text
干净检出 → 按锁文件安装依赖 → 静态检查 → 单元/API 测试 → 构建
                              任一步失败 → 停止后续交付
```

npm 项目可用 `npm ci`，实际脚本名称以 package.json 为准；不存在的 `lint` 或 `test` 不是有效验证。测试需要数据库时提供独立 CI 测试服务，不能借用教师开发库。

部署完成至少验证：health、创建与重查、重启应用后记录保留，以及缺失必需环境变量时清晰失败。镜像标签、迁移版本和回退步骤要进入交付说明。公网部署不是本课最低门槛。


## 自检与参考答案

**问题：** 容器能启动，为什么浏览器仍访问不到 API？

<details><summary>完成思考后查看参考答案</summary>

检查监听地址、端口发布、服务内部地址和代理路径。容器内监听 127.0.0.1 只接收容器自身访问；应用启动成功并不证明端口对外可达。

</details>
