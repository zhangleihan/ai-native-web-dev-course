# 项目关联：把期末UI连接到真实业务数据

## 本讲的最小业务切片

选择期末系统的一种资源，例如案例、任务或工单，先完成“筛选列表→填写表单→服务器确认→重新查询”。保留第4讲组件化成果，让数据来源从静态数组转为明确API，而不一次重写所有页面。

| 层次 | 最小要求 | 验证证据 |
|---|---|---|
| 契约 | 输入、成功与失败形状明确 | 接口表或OpenAPI与真实请求对应 |
| 查询 | 加载、成功、空结果、失败分开 | 当前条件与显示结果一致 |
| 写入 | 草稿、提交中、确认、未确认分开 | 采用服务器id；失败保留输入 |
| 生命周期 | 取消失效读取，阻止旧结果 | 快速切换与卸载有正确清理 |
| 联调 | 页面、代理、API地址明确 | Network和日志可对应 |

本讲独立实验复用第五讲公开API，未包含账号。迁入course-lab时保留其会话和CSRF请求逻辑，不用一个无账号示例替换安全边界。第六讲数据库路线可用于验证服务重启后仍能读取，而本讲内存重启丢失属于预期。

## FDE与Next.js对照

FDE UI原型的本地状态先用于交互设计，不代表真实业务已经写入服务端。为一个具体功能接入API时，说明哪份数据来自服务器、哪份是临时草稿、哪份仍是模拟。

已有Next.js /remote提供只读请求对照。若在服务端组件读取初始数据，再由客户端组件提交，要明确更新后由谁重新查询或使缓存失效；不能假设客户端setState会自动改变服务端缓存。

## 结果检查

新筛选不会被旧响应覆盖；读取失败可见；写入后采用服务器返回值；列表刷新失败不抹掉已确认保存；不在未知写入结果后自动重发。当前筛选不匹配新记录时，能够用详情或独立查询核对。

## 按需拓展

在保留竞态保护的前提下加入搜索防抖；统一错误适配；按第五讲OpenAPI生成类型；测量缓存和请求去重效果；实现服务器端幂等创建。优先验证最小闭环，不以引入工具数量作为完成标准。
