# 实践练习：从真实请求验证界面行为

## 准备

从课程根目录执行：

```bash
cd labs/express-basics
npm ci --ignore-scripts
cd ../integration-basics
npm ci --ignore-scripts
npm run dev
```

打开 http://127.0.0.1:3031 ，准备浏览器Network和API日志。固定三条样本独立于已有3002或course-lab数据。所有故障都是本机课程服务显式注入，不访问真实业务系统。

## 对照一：成功、分页和空结果

正常读取时total=3，每页2条。筛选“链路”应匹配2条；筛选一个不存在的词应显示“没有匹配案例”，而不是错误。

查看Query String中的kw、industry、difficulty、offset、limit。切换筛选后确认offset归零，翻页后条件不丢失。说明total与items.length的区别。

## 对照二：三种读取失败

依次选择HTTP503、200但JSON损坏、200但结构错误，观察分类。三者都不能显示为“没有案例”。切回正常场景后重试读取，记录恢复过程。

HTTP错误可带请求编号；网络或协议问题未必具有完整服务器信息。不要为了凑齐字段而编造requestId。

## 对照三：慢查询与快查询

先慢查链路，再尽快快查订单。确认最终界面对应订单，旧结果或旧错误没有覆盖当前状态。结合client/latest.mjs说明代次检查与AbortController各自负责什么。

如果操作时第一条请求早已完成，不能凭这一轮证明竞态保护；用自动演示和不响应abort的模块测试继续验证。

## 对照四：创建成功与列表刷新

恢复正常查询，填写带首尾空白的唯一标题并提交。观察POST201、服务器id与去空白标题，确认草稿在明确成功后清空，随后发出GET刷新。

再让列表筛选不匹配新标题，或将读取场景设为503后创建。说明为什么“保存已成功”与“列表当前没显示”可以同时成立。不要为了展示新卡片而绕过服务器筛选。

## 对照五：写入结果未确认

表单选择“已写入，但响应被实验服务中断”，提交唯一标题。预期当前代理返回502，页面保留草稿并提示先核对，不自动重发。

恢复正常读取，用该唯一标题查询，应能看到一条已保存对象。记录为什么不能把502直接解释为未写入。本例没有幂等键，避免再次提交同一草稿造成重复。

## 对照六：代理与跨源

从3031页面分别选择同源代理、允许的跨源直连、未开放读取的跨源直连。观察Request URL、Origin、OPTIONS与响应头；Node或curl能读到公开接口，不代表浏览器脚本也被允许读取。

此项必须在浏览器记录，未做就写未验证。不要用关闭安全限制或no-cors模式作为解决方案。

## 自动演示与检查

在实验目录另开终端：

```bash
npm run demo
npm run check
```

demo启动随机端口的独立API与代理，验证6组对照，不修改正在运行的3030/3031数据。check运行8项测试并构建React；CORS测试只核对服务器响应头，不模拟浏览器限制。
