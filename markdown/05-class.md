# 实践练习：逐步完成案例 API

## 输入与准备

阅读本讲概念和Express教程的前5节，使用Node20.18+。从课程根目录进入 `labs/express-basics`，执行 `npm ci` 和 `npm run dev`，检查3002端口健康接口。不要向教材静态站点发送API请求。

本次主线只要求创建、列表、详情与错误输入。筛选分页、PATCH、DELETE及FastAPI作为完成基础后的拓展，避免将抄完完整代码当作学习目标。

## 步骤一：解释一次读取

请求 GET /api/cases，初始应为200和空items；请求一个不存在的详情，得到404。定位app.mjs中的挂载位置、cases-router.mjs中的处理函数和memory-store.mjs中的存储方法。用自己的话说明调用顺序。

## 步骤二：创建后读取

使用requests.http或教材curl提交合法案例。记录201、Location与返回id，按Location读取详情，再查询列表。说明id由哪一端生成，为什么不允许客户端指定。

## 步骤三：从失败层次验证输入

依次提交空白标题、非法难度、额外owner字段、坏JSON以及text/plain。前三类为400校验失败，坏JSON为400解析失败，内容类型错误为415。每次失败后查询列表，确认总数未增加。保存响应的requestId，找到对应日志。

## 步骤四：观察数据生命周期

创建记录后刷新浏览器，记录仍存在；停止服务并重新启动，列表为空。再用npm run dev修改一个源码文件，观察热重载也可能清空内存。说明这是进程生命周期，不是前端状态丢失。

## 步骤五：完成后扩展

筛选得到两条记录，用limit=1验证total仍为2；PATCH只改标题并检查其他字段；DELETE后检查204无响应体，随后GET为404。执行npm test，与手工观察对应。

Python路线可改做labs/fastapi-basics中的创建、读取与失败输入，但必须解释422/detail与Express的400/error差异。两套框架不要求全部提交。

## 拓展：用OpenAPI驱动一轮联调

在完成基础请求后，按[OpenAPI工具教程](#/part/5/g)启动labs/api-design-tools。先运行npm run check，再用3020的Swagger UI创建案例、读取详情、局部修改和触发400。分别指出规范样例、生成类型与真实响应。解释lint、TypeScript检查和响应Schema验证各自发现什么问题。该拓展复用已有Express代码但使用独立数据，不改变正在运行的3002实例。
