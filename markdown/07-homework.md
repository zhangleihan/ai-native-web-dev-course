# 课后练习：一个可可靠联调的资源页面

## 必做（建议45–60分钟）

把期末项目UI中的一个资源连接到真实或独立模拟API，完成筛选列表与创建表单。查询需区分加载、非空、空结果和失败；快速切换不显示旧结果。提交中防重复进入，成功使用服务器id，失败保留草稿，未知结果不自动重发。

可以基于本讲实验改写业务主题，不要求调用模型或云服务。保留模拟与内存说明，不能把静态数组描述为持久数据库。

## 分步完成

1. 写出列表参数、创建输入、成功对象与错误结构，标明与后端版本的对应关系。
2. 接入业务请求模块，将HTTP解析和组件渲染分开。
3. 完成当前请求保护与清理，解释依赖项为何这样设置。
4. 验证一次成功、一次空结果、一次读取失败及一次提交后的核对。
5. 记录浏览器联调结果；未验证的跨源或部署条件单独说明。

## 提交内容

通过北邮云邮教学空间提交源码或仓库、相对路径运行步骤、请求记录与约200字说明。说明至少解释“旧响应为什么不能覆盖”和“写入结果未确认为什么不能直接重发”。使用AI时说明参与范围和一次人工核查，不提交密钥、口令或私人对话。

## 自评标准

| 维度 | 完成标准 |
|---|---|
| 契约 | 实际请求与后端参数、状态和结构一致 |
| 查询 | 四种反馈可区分，分页/筛选不丢条件 |
| 写入 | 使用服务器确认值，保存与刷新结果分开 |
| 生命周期 | 失效请求清理，旧结果与旧错误不会覆盖 |
| 证据 | 记录可复现，模拟及未验证范围清楚 |

## 选做

加入防抖并比较实际请求数；为PATCH或DELETE补充失败恢复；实现OpenAPI类型生成与运行时校验的组合；为创建设计服务器端幂等策略。不要只为每行实现复制一条同义断言，测试应维护具体行为承诺。
