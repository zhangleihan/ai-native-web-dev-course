# 课后练习：案例排序与数据流复盘

## 必做：在前面的练习成果上增加排序

保留标题与难度筛选，新增“默认顺序 / 标题升序”选择器。排序条件放在与筛选条件相同的状态拥有者中，结果先过滤再排序。不直接对原始 initialCases 调用 sort；需要排序时复制数组，并使用 `a.title.localeCompare(b.title, 'zh-CN')` 比较标题。清空筛选时把排序也恢复默认。

使用稳定 id 作为 key。不要把排序结果、可见数量再存一份 state，也不要通过 querySelector 手动重排 React 列表。建议先保留3条已有数据，再加一条带独立 id 的自选案例，写清新增后各场景预期数量。

验收至少覆盖：默认顺序、标题排序、关键词与难度组合、无结果、重置后恢复原顺序。排序结果受实际标题及运行环境的中文排序规则影响，应记录实际顺序；核心要求是原始数组未被改动、筛选语义正确、重置可恢复。

## 解释题

用自己的代码回答，每题2–4句：

1. 哪些字段是 state，哪些是派生值？为什么？
2. 子组件输入变化后，数据经过哪些函数回到界面？
3. 为什么 `[...items]` 不足以让随后对 `items[0].title` 的修改安全？
4. 为什么收藏数组更新适合使用函数式 setter？为什么 key 不用随机数？

## 提交与评价

按课程云邮任务提交源码、启动说明、测试记录和解释题。提交时不包含 node_modules、dist 或无关下载资料。若使用 AI，附一条关键提问、采用的改动及自己的验证结果；“AI 说可以”不作为验证依据。

本练习的自评标准为100分：功能与边界40分、组件和状态设计30分、可复现测试记录20分、解释与来源10分。具体计分以课程平台公布的任务为准。能运行但无法解释状态拥有者或直接修改 props 的实现，需要修正后再验收。

## 选做一项，勿同时扩张范围

- 增加案例标题编辑：用 map 与对象展开更新指定 id，演示旧引用没有被直接修改。明确编辑草稿与已保存标题是两种不同状态。
- 增加新增案例表单：拦截默认提交，trim 后拒绝空标题；新 id 在提交事件中生成一次。提交成功清空表单，失败保留输入。
- 将阶段三收藏功能迁移到自己的排序版本，证明排序、筛选和收藏不会错配身份。

本页排序练习只使用组件自身的状态；路由、跨页共享状态和后端持久化将在拓展内容与后续章节中使用。第7讲接入 API 时再讨论加载、错误和请求生命周期。
