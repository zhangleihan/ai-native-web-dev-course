# 氛围编程案例：FDE 工作台的整体 UI 设计

## 案例目标与依据

本案例以已有的 `FDE-Workspace` 为对象，学习如何通过氛围编程，将一份复杂的业务设计转化为结构统一、可以交互的系统界面。FDE 工作台围绕“业务问题到 AI 系统交付”组织案例、项目、智能体、审批、部署与评测，不是简单的列表增删改查应用。

本节依据仓库中的功能设计文档、`web/src` 源码、项目说明及已有截图重建实现过程。**下文的轮次与提示词是根据现有成果整理的教学复现方案，并非原始聊天记录或已核实的历史生成顺序。** 核查目录没有 Git 历史可供追溯，也未发现完整的原始生成对话。

当前原型使用 Next.js 14、React 18、TypeScript、Ant Design 5、React Flow 11。具体安装版本以 `web/package-lock.json` 为准。它与前面 Next.js 入门实验的依赖版本不同，阅读时不要直接混用配置或旧版、新版组件属性。

本案例在 `labs/fde-ui-case` 提供 FDE 界面的独立可运行副本，不修改 FDE 原项目。截图取自该仓库的既有资料，用来观察布局与信息层级，不代表本次重新运行得到的测试结果。

## 1. 先读懂业务主线，再规划页面

功能设计文档给出的主线可以整理为：

```text
行业案例 → 业务发现 → 问题定义 → 业务建模 → 方案设计
→ 智能体构建与受控运行 → 部署演示 → 效果评测 → 复盘沉淀
```

先确定三个问题：使用者现在处于哪个项目？处于哪个阶段？下一步需要完成什么任务？这三个问题决定了全局项目切换、阶段导航和页面主操作的位置。

| 使用情境 | 界面需要表达的信息 | 对应模块 |
|---|---|---|
| 开始一次实训 | 案例背景、难度、业务约束 | 案例库、案例详情 |
| 进入项目继续工作 | 当前项目、阶段进度、待办事项 | 工作台、项目总览 |
| 访谈并澄清问题 | 受访者、对话、待确认洞察 | 业务发现、问题定义 |
| 设计 AI 方案 | 业务对象、关系、方案字段、系统组件 | 本体建模、方案设计 |
| 检查一次运行 | 当前状态、调用步骤、审批内容 | 智能体、运行轨迹与审批 |
| 说明项目结果 | 部署阶段、评测证据、成果报告 | 部署、评测与成果 |

设计文档描述的是产品目标，源码体现的是当前实现。前者提到的真实部署 URL、模型调用和权限治理，不能因为页面上有对应按钮就认定已经实现。现有 `web/README.md` 明确说明：数据为前端模拟，运行、审批和部署为脚本化演示，无真实后端和数据库。

### 第一轮提示：把产品文档转为 UI 规格

在 FDE 项目副本中，向 AI 提供功能设计文档、`web/README.md` 和 `web/package.json`：

```text
请先阅读现有资料，不修改代码。
围绕“案例进入—业务发现—问题定义—方案设计—受控运行—评测”整理 UI 规格。
按用户任务划分模块，不要把文档的每一个章节都机械变成菜单。
输出角色与任务表、页面清单、页面之间的跳转、各页输入与操作后的结果。
区分已有界面、需要模拟的交互和不在本次范围内的真实后台能力。
第一阶段只实现一个通信网络故障案例的完整演示路径。
```

产物可保存为 `docs/ui-brief.md`。检查规格时，重点看页面之间能否形成操作链，而不是页面数量是否足够多。

## 2. 用共享外壳建立信息架构

现有工程的 `AppShell.tsx` 将页面分成全局入口、项目工作区、智能体工作区、交付和管理后台。顶栏保留当前项目、阶段、Copilot 入口、审批提醒与演示角色。这样切换页面后，用户仍能判断“我在哪个项目里”。

![FDE 工作台：全局导航、当前项目、指标与阶段进度](assets/fde-ui/02-home.png)

图中工作台不是单纯的欢迎页：顶部给出继续项目的入口，中部用指标与阶段条概括进展，下部呈现待办与团队信息。截图中的分数、成本、角色姓名等均属于原型展示内容，不应作为真实业务统计使用。

| 界面区域 | 现有实现 | 设计目的 |
|---|---|---|
| 左侧导航 | `components/AppShell.tsx` | 按工作阶段分组，保持全局位置感 |
| 顶部项目栏 | AppShell 中的项目切换菜单 | 保留当前项目上下文 |
| 主内容区 | `.fde-page` | 统一页面边距与最大宽度 |
| 标题与主要操作 | `PageHead` | 每页先说明任务，再提供主要动作 |
| 阶段进度 | `StageBar` | 将“当前阶段”变成可见的导航 |
| 全局辅助区 | `CopilotDrawer` | 按需展开辅助信息，减少主页面干扰 |

### 第二轮提示：先搭导航和占位页面

```text
使用现有 Next.js App Router、TypeScript 与 Ant Design，先实现全局外壳。
抽出 AppShell，左侧按项目工作区、智能体工作区、交付、后台分组。
顶栏固定显示当前项目和阶段，提供项目切换、演示角色与 Copilot 入口。
先为各路由建立带标题与说明的占位页面，确保导航高亮和详情路由正确。
本轮不要一次实现全部业务，也不要复制出多个各自维护的顶栏。
完成后列出路由到文件的映射，并逐项检查跳转。
```

现有路径包括 `/cases`、`/cases/[caseId]`、`/project/[projectId]/discover`、`/project/[projectId]/design` 与 `/project/[projectId]/trace`。通信案例的项目编号为 `p-2024-07`，可以据此定位完整路由。实际工程还包含 `/proposal` 项目预算页面；因此不能只照搬 README 中较早的“19页”统计，页面范围应以 `src/app/**/page.tsx` 为准。

## 3. 将视觉要求落实为设计变量

“专业一些”不是可执行的视觉要求。需要明确主色、背景、间距、控件密度、标题层级以及状态颜色的含义。

现有 `lib/theme.ts` 和 `app/globals.css` 已提供统一约定：

| 设计项 | 源码中的值或规则 | 用途 |
|---|---|---|
| 主要操作色 | `#1677ff` | 主要按钮、当前阶段与选中状态 |
| 页面背景 | `#f4f6fb` | 区分白色内容面板与工作区 |
| 侧栏基色 | `#101728` | 将全局导航与编辑区域分开 |
| 次级边框 | `#e6ebf3` | 面板、表格和画布边界 |
| 基础字号与控件高度 | 13px、32px | 支持信息密度较高的桌面工作台 |
| 基础圆角 | 8px | 统一控件与面板形态 |
| 侧栏宽度、顶栏高度 | 228px、56px | 建立稳定的应用框架 |
| 内容宽度与边距 | 最大1680px；内边距20px / 24px / 40px | 控制大屏阅读与编辑空间 |

以上是对现有原型的观察，不是所有系统都必须采用的标准。FDE 示例保留其深色导航与浅色工作区；教材网页自身仍保持白底简洁风格。

### 第三轮提示：集中管理主题，减少逐页修补

```text
先整理 theme.ts 和 globals.css，再完善各业务页。
以蓝色表示主要操作和选中状态；用统一的成功、警告、错误颜色表达运行状态。
共享外壳、标题、卡片、表格、标签和表单保持一致。
页面内容采用白色面板和浅色工作区，控制文字层级与留白。
不要为每页创建不同的按钮尺寸，也不要把装饰颜色当作业务状态。
给出修改前后的设计变量表，并检查至少两个不同类型页面。
```

源码的 `riskColor`、`permissionColor`、`statusColor` 将风险、工具权限、运行状态分开映射。绿色“允许”与绿色“运行完成”在颜色上相近，但必须同时保留文字，不能让用户仅凭颜色猜测含义。

## 4. 按工作任务设计三类页面

整体 UI 不意味着把每一页做成同一种表格。FDE 原型中至少有三种不同的工作方式：检索选择、分析编辑、过程检查。

### 4.1 案例库：先找到任务，再进入项目

`app/cases/page.tsx` 将行业、难度与关键词保存在页面状态中，组合计算可见案例。筛选结果由 `cases.filter(...)` 得出，不再保存另一份结果状态。卡片展示摘要、标签等信息，点击后进入案例详情。

复现时可先完成一张案例卡片，再扩展为数组渲染。不要一开始就同时生成全部页面；先验证筛选与详情跳转正确，再补充更多模拟记录。

### 4.2 业务发现：把对话转化为可确认的成果

![FDE 业务发现：访谈对象、对话与结构化洞察](assets/fde-ui/07-discover.png)

该页面采用三栏结构：左栏选择受访者并展示背景，中栏进行访谈，右栏检查结构化洞察。关键不是“有一个聊天框”，而是访谈回答如何成为可接受、可修改、可拒绝的信息。

实际代码把输入框、当前受访者、编辑草稿放在页面局部状态中；访谈记录和洞察通过 `useStore()` 共享。`ask` 根据预设脚本生成演示回答，再调用 `pushTurn`、`addExtracts` 等动作。这里的“AI 提取”由脚本模拟，并没有调用真实模型。

### 第四轮提示：实现一条有结果的业务交互

```text
实现 Discover 页的三栏布局：受访者和背景、访谈区、结构化洞察。
使用预设问题与回答，不调用模型。明确展示模拟模式。
选择推荐问题后增加对话记录，并把对应候选洞察加入右栏。
每条洞察包含类型、来源、置信度和确认状态，支持接受、编辑、拒绝。
输入草稿留在页面组件，已确认洞察进入共享状态。
先用一个受访者验证完整链路，再扩展其他受访者。
```

检查时应记录：提问前后对话如何变化、增加了哪些候选信息、接受或拒绝是否只改变目标记录。置信度是模拟数据字段，不是模型准确性的证据。

### 4.3 方案设计：文字方案与图形结构互为补充

![FDE 方案设计：运行底座、方案字段与架构画布](assets/fde-ui/10-design.png)

方案设计页由运行底座选择、方案字段、组件面板、架构画布和建议区组成。文字区解释“为什么这样设计”，画布展示“组件如何连接”，两者不能互相替代。

现有 `FlowCanvas.tsx` 统一节点样式、连线、缩放控件与可选缩略图。`design/page.tsx` 根据 `dataset.design` 生成初始节点，并通过 `extraNodes` 增加节点。方案字段和新增节点属于该页局部状态，不应在教材中描述为已经跨页持久化的设计成果。

### 第五轮提示：先复用画布，再补编辑能力

```text
封装 FlowCanvas，输入 nodes、edges 和节点点击回调。
方案设计页左侧为方案字段，右侧为组件面板和架构画布。
先支持预设节点展示、缩放和点击查看，再实现点击组件面板新增节点。
统一节点的标签、类型颜色和信息密度。
明确哪些改动只保存在当前页面；不要声称拖动或连线已经保存。
用同一封装支撑本体图、方案图和工作流，避免重复实现三套画布。
```

当前封装设置了 `nodesDraggable`，但没有提供完整的节点变化持久化接口，并设置 `nodesConnectable={false}`。因此，“看到画布”不等于“已实现可保存的流程编辑器”。将拖动位置保存、连线校验和撤销重做列为后续改进更准确。

## 5. 让整体 UI 由同一份状态驱动

在大型原型中，最常见的问题是单页看起来完整，切换页面后数据却互不相干。FDE 的共享状态位于 `lib/store.tsx`，由根布局包裹所有页面。

```text
app/layout.tsx
  → AntdRegistry：首屏样式
  → ConfigProvider：主题与中文组件文案
  → StoreProvider：项目、角色、访谈、运行与记忆等状态
  → AppShell：全局导航和上下文
  → 当前页面：读取数据，触发业务动作
```

| 状态 | 当前源码中的位置 | 设计上的意义 |
|---|---|---|
| 项目与数据集 | StoreProvider / getDataset | 全局导航与各页使用当前项目 |
| 角色 | StoreProvider / setRole | 演示不同角色看到的内容 |
| 案例关键词、行业、难度 | CaseLibraryPage | 页面内的检索条件 |
| 访谈记录、候选洞察 | StoreProvider | 允许多个区域围绕同一成果更新 |
| 方案字段、新增架构节点 | DesignPage 局部状态 | 当前仅为页面内编辑 |
| 运行状态、步骤与审批 | StoreProvider | 智能体页、轨迹页与顶栏提醒联动 |
| Copilot 是否展开 | StoreProvider | 全局入口控制抽屉 |

项目切换会重新装载该项目的演示状态，刷新也会恢复初始数据。角色选择是演示状态，不构成登录认证；界面上隐藏信息也不等于服务端权限控制。

### 第六轮提示：按行为设计共享状态

```text
检查各页是否重复保存了同一份项目或运行数据。
把需要跨页面同步的数据放入 StoreProvider，提供清楚的业务动作。
保留搜索词、临时标签页和编辑草稿等局部状态。
切换项目时清理未完成的模拟定时任务，重新载入对应数据集。
分别说明跨页保留、切换项目重置、刷新重置三种行为。
不要为了“统一状态”把所有输入框都塞进全局 Context。
```

## 6. 从静态状态标签走向可解释的执行过程

![FDE 运行轨迹：未运行时的提示、统计区与步骤详情](assets/fde-ui/15-trace.png)

这张既有截图处于尚未运行状态。页面提供明确的运行入口，左侧等待执行步骤，右侧等待选中步骤后的详情，避免用一张空表格让用户猜测下一步。

原型执行逻辑位于 `startRun`、`playSteps` 和 `decideApproval`：定时任务逐步添加运行片段，遇到需要审批的步骤进入等待状态，批准与拒绝选择不同的后续脚本。

```text
初始 → 运行中 → 等待审批
                 ├─ 批准 → 继续运行 → 完成
                 └─ 拒绝 → 取消
```

运行片段（Span）描述一次上下文构建、模型步骤、检索或工具操作；运行轨迹（Trace）把这些片段组织为一次执行过程。原型中的 Token、成本与时长由模拟片段累计，不是实际模型计费。

### 第七轮提示：设计成功、等待与拒绝三条路径

```text
实现“启动运行—等待审批—批准或拒绝—结束”的模拟状态机。
运行页、轨迹页和顶栏待审批数量必须读取同一个 run。
轨迹页左侧展示步骤，选中后右侧展示输入、输出和状态。
等待审批时显示动作、影响和决策入口，不能提前显示执行成功。
批准与拒绝走不同分支，并同步改变日志、最终状态与页面提示。
明确它是前端模拟，不实现真实工具执行或权限保障。
```

这是将业务规则转为交互的核心步骤。单纯把“批准”按钮改成绿色，并不能说明流程正确；需要观察审批后是否继续增加步骤，以及拒绝后是否进入不同结果。

## 7. 用具体问题驱动视觉与交互迭代

下一轮提示应来自观察到的问题，包含页面、复现操作、当前表现、期望结果和修改范围。以下是**复现练习情境**，不表示所有问题都已经修复。

| 问题类型 | 可执行的迭代要求 |
|---|---|
| 菜单过多 | 按工作阶段分组；保持当前项高亮，不将每个配置字段变成一级入口 |
| 三栏信息争抢空间 | 业务发现页优先保证对话与洞察可读，背景说明保持次级层级 |
| 图与表不一致 | 指出共享状态拥有者，禁止页面分别修改各自的初始数组 |
| 不知道为何等待 | 在审批区明确待批准动作与影响，不只显示加载动画 |
| 中文夹杂过多 | 将用户可见标题改为自然中文，首次出现时补充英文术语；代码标识符保留 |
| 小屏横向溢出 | 检查固定侧栏、顶栏项目摘要和三栏网格；表格局部滚动，阅读区可堆叠 |

```text
请检查 Discover 页面在较窄窗口下的布局。
现有页面包含受访者、对话和洞察三个区域。优先保证输入与主要操作可见，
在宽度不足时调整区域排列，避免整个页面横向滚动。
只改布局和可访问性，不改访谈脚本、状态结构与已确认数据。
报告具体修改、桌面与窄屏检查结果，以及仍未解决的问题。
```

现有案例库使用固定 `Col span={8}`，全局外壳使用固定宽度侧栏。它们说明该原型首先面向桌面工作台，不能仅凭截图宣布已完成手机适配。键盘操作、对比度、空结果恢复和焦点管理也应作为后续检查项。

## 8. 运行、核对与记录

课程已包含完整前端副本，无需另行获取 FDE 原工程。从课程仓库根目录执行：

```bash
cd labs/fde-ui-case
npm ci
npm run typecheck
npm run dev
```

使用 Node.js 20，按终端输出打开本机地址；项目默认端口为3100。若已有服务运行，直接访问已有实例或选择空闲端口，不使用强制结束其他进程的参数。生产构建可执行 `npm run build`，副本保留原依赖版本，不连接真实后端。

| 检查步骤 | 应观察到的结果 | 记录内容 |
|---|---|---|
| 选择演示角色并进入工作台 | 角色与当前项目可见 | 角色、项目、所见入口 |
| 案例库组合筛选并进入详情 | 筛选结果与详情目标一致 | 筛选条件与案例编号 |
| 在通信项目中进行一次推荐访谈 | 对话增加，洞察进入待确认区 | 问题、候选及接受/拒绝结果 |
| 在方案设计页添加节点 | 当前画布出现相应节点 | 节点类型与当前页面状态 |
| 启动运行后切换到轨迹页 | 能看到同一运行的步骤与状态 | 运行状态、片段数、审批提示 |
| 分别演示批准与拒绝 | 结束状态与后续轨迹不同 | 两次独立运行的结果 |
| 切换项目或刷新 | 按原型约定重新载入初始状态 | 哪些内容被重置 |

操作路径可使用 `/project/p-2024-07/discover`、`/project/p-2024-07/design`、`/project/p-2024-07/agents` 和 `/project/p-2024-07/trace`。不要把浏览器中成功切换演示角色作为真实权限测试。

保存“需求版本—关键提示词—修改文件—验证结果”的对应记录。没有运行的步骤标为未验证；截图和源码检查不能替代运行测试。

## 9. 将设计过程迁移到自己的项目

先确定一条完整业务主线，再选择几种适合任务的页面类型；用共享外壳与设计变量维持视觉一致，用明确的状态拥有者维持交互一致。每轮只增加一组可以验证的能力。

可复用的是需求拆解、页面组织、组件边界和验证方法，不是 FDE 的全部菜单。第二次平时作业只需围绕自己的核心流程实现 UI，并说明哪些数据是模拟、哪些动作已经接通服务。
