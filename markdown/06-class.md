# 实践练习：从建模到持久化案例API

## 输入与准备

阅读本讲核心概念与SQL教程前5节，准备Node20.18+。从课程根目录进入labs/database-basics，执行npm ci、npm run migrate、npm run seed。默认路线使用文件型PGlite，不要求Docker、模型账号或PostgreSQL服务。

本次必做聚焦案例表、约束、查询和重启后读取；作者/标签JOIN、事务和计划作为逐步拓展。所有操作使用本实验的数据目录或独立练习库，不复用真实业务库。

## 步骤一：先解释模型

定位sql/001_schema.sql，标出四张表的主键与外键。说明为何案例作者是一对多、案例标签是多对多，为什么author_id可为空，为什么联合主键包含两个编号。

## 步骤二：查询与预测结果

执行npm run sql -- sql/queries.sql。先预测，再核对：通信行业3条；LEFT JOIN得到5条案例；作者案例数量2、1、0；未指定作者2条。若已经改动样本，说明预期为何变化。

## 步骤三：直接挑战约束

用新的测试编号提交空白标题、非法难度、重复作者名和未知作者编号。记录SQLSTATE与失败原因；再查询确认错误没有写入。理解API校验与数据库约束如何互补。

## 步骤四：验证持久化接口

启动npm start，检查3003端口storage=pglite。POST创建并保存Location；停止后重新启动服务，再GET该路径。记录浏览器刷新、服务重启、换数据目录三个行为的区别。

## 步骤五：事务与查询计划

停止API后执行sql/transaction.sql，观察临时标题出现后回滚。运行npm test，检查第二步外键失败没有留下新案例。再执行sql/plan.sql，解释计划中的扫描方式，不照抄别人的耗时数字。
