# 项目关联：从模拟状态到可调用服务

## 本讲在主线中的位置

前四讲建立了React界面与系统原型，本讲为资源提供独立HTTP入口。第6讲解决持久化，第7讲接通前后端请求，第8讲增加身份和权限。接口可以先于界面独立验证。

| 当前界面数据 | 后端契约 | 接入时需要处理 |
|---|---|---|
| 本地案例数组 | GET /api/cases | 加载、空结果、筛选参数与失败 |
| 当前选中对象 | GET /api/cases/{id} | 不存在、请求取消和返回导航 |
| 表单提交到本地state | POST /api/cases | 校验反馈、201与新资源编号 |
| 局部编辑 | PATCH /api/cases/{id} | 未提交字段保持、保存成功或失败 |

FDE UI副本仍使用前端模拟状态。本表是后续接入建议，不表示现有访谈、运行、审批与记忆数据都已由API承载。先选择一个集合完成贯通，再处理复杂流程。

## 代码阅读路线

使用labs/express-basics理解没有认证与数据库的请求链，再进入labs/course-lab：阅读server/app.mjs的GET /api/cases，追踪存储方法；随后比较创建接口如何要求登录。综合实验包含会话与其他规则，不能直接照搬入门实验的匿名创建请求。

已有Next.js项目可用Route Handler实现同一契约；需要Python依赖时可选FastAPI。框架替换前核对字段、状态码、错误结构与认证方式，基础FastAPI实验当前只实现列表、详情、创建，尚不覆盖全部Express拓展能力。

## 最小完成范围

为自己项目的一个资源实现可独立调用的集合、详情与创建。用明确的请求验证操作结果，再准备将前端数据入口替换成fetch。此阶段应能说明每项数据在哪个进程、什么操作导致重置。

## 选修拓展

增加分页、局部更新和删除，记录空结果与失败的区别。数据库、权限与并发控制分别衔接后续讲次，不将本地内存示例直接作为生产实现。
